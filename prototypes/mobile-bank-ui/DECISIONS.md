# Решения по UI-прототипу next_offer

**Дата:** 13.11.2026  
**Контекст:** выбор UI для MVP агента «Проактивный консьерж».  
**Файлы:**
- `prototypes/mobile-bank-ui/index.html` — три начальных варианта (A, B, C)
- `prototypes/mobile-bank-ui/final.html` — финальный комбинированный прототип
- `prototypes/mobile-bank-ui/design-system.css` — дизайн-код для переноса в React

## Вопрос прототипа

Как должен выглядеть веб-интерфейс, в котором клиент получает проактивные банковские предложения?

## Рассмотренные варианты

| Вариант | Описание | Вердикт |
|---|---|---|
| **A** | Горизонтальная карусель баннеров под шапкой дашборда | ✅ Взяли |
| **B** | Лента офферов друг под другом в основной колонке | ❌ Отказались |
| **C** | Toast-уведомления в правом верхнем углу при новом событии | ✅ Взяли |

## Итоговое решение

Совместить **A + C**:

- **Карусель баннеров (A)** — постоянная плашка персональных предложений в верхней части дашборда. Пользователь всегда видит актуальные офферы при входе.
- **Toast-уведомления (C)** — мгновенная обратная связь при появлении нового оффера после события. Дублирует свежий оффер из карусели, чтобы привлечь внимание.

Лента (B) отклонена: на десктопе занимает слишком много вертикального пространства и размывает фокус. Карусель + toast даёт и обзор, и акцент.

## Дизайн-код

### Структура баннера

Каждый баннер состоит из:

- **Фон** — градиент, привязанный к типу события/продукта.
- **Заголовок** — главная выгода (1 строка).
- **Подзаголовок** — краткое пояснение (1–2 строки).
- **Иконка** — emoji/пиктограмма в правом нижнем углу, полупрозрачная.
- **Кнопка закрытия** — `×` в правом верхнем углу.

### Цветовая схема по типам событий

| Тип события | Градиент | Иконка | Назначение |
|---|---|---|---|
| `salary` | `#7c3aed → #db2777` | 💰 | Зарплата/премия → накопительный счёт |
| `purchase` | `#2563eb → #06b6d4` | 🏠 | Крупная покупка → целевой накопительный счёт |
| `deposit_view` | `#ea580c → #f59e0b` | 📈 | Просмотр вкладов → повышенная ставка |
| `high_balance` | `#059669 → #10b981` | 💳 | Высокий остаток → перенос на накоп. счёт |

> Цвета и иконки хранятся в `banner_templates` (поля `background_color`, `icon`). Добавление нового типа баннера не требует изменения фронтенда.

### Расположение

- **Карусель** — в верхней части главного экрана, горизонтальный скролл.
- **Toast** — фиксированный контейнер `top: 80px; right: 24px; width: 360px`.
- **Симулятор событий** — правая панель (админ-зона для демо).

### Поведение

1. **Симуляция события** → создаётся оффер.
2. Оффер сразу появляется:
   - в карусели (первым элементом);
   - во всплывающем toast.
3. Toast автоматически скрывается через 8 секунд.
4. Пользователь может закрыть баннер — оффер удаляется из обоих мест.
5. **Polling** — фронт раз в 3 секунды опрашивает backend на предмет новых офферов.

## Задел на расширение

- Тип баннера — отдельная колонка/сущность в БД (`banner_templates.type`).
- UI стилизуется по данным из шаблона, поэтому новый тип = новая строка в БД.
- Toast и карусель используют один и тот же компонент баннера.

## Открытые вопросы

- Какой точный action при клике на баннер? (переход на экран продукта / модалка / чат)
- Нужна ли группировка нескольких toast подряд?
- Как обрабатывать accept/decline внутри баннера (дополнительные кнопки)?
- Rule engine и LLM отложены; после их появления логика создания оффера изменится, но UI-решение остаётся в силе.
